# 真实托管服务接入计划

目标：落实已获用户授权的 GitHub Pages + Supabase + 模型 API + 合规邮件账单方案。用户授权由我选择提供商；账号条款、新密码及服务密钥由用户本人完成。

## 服务选择与数据流

- Supabase 新加坡免费项目 `fsgeecoskegtvwhatsvn`，数据库启用 RLS，云函数自行鉴权。
- GitHub 仓库 `huyarufitor/family-finance`，Pages 构建时仅注入公开配置。
- 模型：阿里云百炼兼容接口，按用户账号可用模型及免费额度联调。
- 邮件：Resend 托管收件地址与签名 webhook。Pipedream 公告工作流将于 2027 年停用，因此不采用。
- 第一条可靠自动同步路径：用户将官方 CSV 账单附件发送/规则转发到渠道专用收件地址，签名校验、匹配账户、解析、复用 import-bills 幂等接口。
- 收件地址按渠道绑定固定家庭与账户；不读取整个邮箱。只接受用户选定的转发发件人，真实财务数据开始传输前明确来源和目的地。
- 支持 UTF-8/GB18030 CSV；PDF、Excel、加密 ZIP 与不明确正文应明确失败，不推断交易。
- 不在日志输出邮件正文、附件、模型密钥或渠道 token。

## 顺序

1. 部署现有迁移和函数，确认数据库表及 RLS、匿名请求拦截。
2. 配置 Pages、构建变量、站点回调地址和 CORS。验证真实部署 HTTP200。
3. 测试先行：签名伪造/过期拒绝、收件地址与允许发件人隔离、CSV 编码与附件限制、重试幂等。
4. 提取前后端共用 CSV 解析器；添加邮件渠道元数据迁移、email-bills 签名接收函数。保持渠道哈希鉴权，不存原始 token。
5. 用户账号与密钥就绪后配置模型、Resend webhook，使用合成邮件联调。登录提供商另行配置，默认邮件服务不可视为家人均可用。
6. 运行 lint、前后端 typecheck、单元测试、浏览器测试和生产构建。记录每一项真实部署与未完成阻塞。
